# バックアップからの復旧手順

毎日 JST 3:00 に、本番DBのdumpが GitHub Actions の Artifacts に保存されています。
**保持期間は90日**です。それより前のものは自動的に消えます。

---

## 1. バックアップを取り出す

1. GitHub → リポジトリ → **Actions** タブ
2. 左の「本番のバックアップと検証環境への複製（毎日）」を選ぶ
3. 戻したい日付の実行を開く
4. ページ下部の **Artifacts** から `db-backup-YYYYMMDD` をダウンロード
5. zipを展開すると `my-teas-backup-YYYYMMDD.sql.gz` が入っています

---

## 2. 中身を確認する（パソコンで）

```bash
# 解凍
gunzip my-teas-backup-20260821.sql.gz

# 中身をざっと見る
head -50 my-teas-backup-20260821.sql
grep -c "INSERT INTO" my-teas-backup-20260821.sql
```

---

## 3. まず検証環境で試す ★重要

**いきなり本番に流し込まないこと。** 必ず検証環境で結果を確認してから本番に適用してください。

```bash
psql "検証環境の接続文字列" -f my-teas-backup-20260821.sql
```

検証環境で、戻したかったデータが正しく復元されているかを Table Editor や SQL Editor で確認します。

---

## 4. 本番へ復元する

dumpは `--clean --if-exists` 付きで作られているため、**流し込むと現在の本番データは消えて、その日の状態に置き換わります。**

**全部戻す場合**

```bash
psql "本番の接続文字列" -f my-teas-backup-20260821.sql
```

**一部のテーブルだけ戻したい場合**

全体を流すと他のテーブルまで巻き戻ってしまいます。その場合は、dumpから必要な部分だけを取り出して実行してください。

```bash
# 例: reviews テーブルに関する行だけを抜き出す
grep -n "reviews" my-teas-backup-20260821.sql | head -50
```

判断に迷う場合は、この手順書と対象テーブル名を伝えて相談してください。

---

## 注意点

- **このバックアップには個人情報が含まれます**（メールアドレス・表示名）。検証環境の匿名化は復元後に別途行われるもので、dump自体は本番そのままです。取り扱いに注意してください。
- **Storage（画像）は含まれません。** `avatars` / `home-ads` のファイルは別途 Supabase のダッシュボードから手動でダウンロードする必要があります。
- 90日より前に戻す必要が出る可能性を考えると、**重要な節目では手元にもダウンロードして保管**しておくと安心です。
